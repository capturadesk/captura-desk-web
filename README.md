# Captura Desk website

Static product website for Captura Desk. This is a separate project from the desktop application; it does not import files from the app at runtime or build time.

## Run locally

Use Node.js 22.18 or newer:

```powershell
npm ci
npm run dev
```

Open the local URL printed by Vite. The development server normally uses http://127.0.0.1:5173. If the desktop app's dev server is using that port, Vite chooses another available port.

## Build and preview

```powershell
npm run build
npm run preview
```

The build creates seven HTML documents in `dist`: overview, getting started, download availability, changelog, privacy, support, and a 404 page. Content is pre-rendered at build time; no server-side runtime is required. JavaScript adds use-case tabs and the copy button. Navigation, FAQs, and core content work without JavaScript.

Upload the contents of `dist` to a static host. Configure the host to serve directory `index.html` files and `404.html` for missing pages. This is a multi-page site; do not rewrite every request to the home page. Relative asset and navigation links support a root domain or a subdirectory. For subdirectory hosting, set `SITE_BASE_PATH` to that directory (for example `/captura-desk/`) before building so the custom 404 page also resolves its assets correctly. The default is `/`. Serve over HTTP(S), rather than opening HTML files directly from the filesystem. No deployment has been configured or performed.

## Project map

- `src/App.tsx`: page content, shared header/footer, FAQs, and use cases.
- `src/site.ts`: page metadata and links to the app repository.
- `src/styles.css`: responsive layout and the desktop app's neutral visual language.
- `src/components/ui`: local shadcn/ui Button and Tabs, adapted from the desktop app.
- `src/main.tsx`: hydrates existing static content; renders pages during development.
- `src/entry-server.tsx` and `scripts/prerender.mjs`: build-time HTML generation.
- `public/images`: app icon and actual sample-workflow screenshot. The screenshot was taken in a fresh isolated app profile, with sample content only.
- `tests/site.spec.ts`: page, asset, navigation, mobile layout, clipboard, and no-JavaScript checks.

## Content and release maintenance

The site currently describes the development build, not a published installer. There is no pricing, signup flow, account system, analytics, or commercial offering. AI API billing is separate and is explained in the site content.

When a Windows installer is available, replace the availability copy and add a link to the actual published release in `src/App.tsx`; do not add a placeholder download URL. Update the changelog from the desktop app's release notes. Keep privacy information aligned with the app's real data handling and review host-specific logging information before publishing.

The production address is **https://capturadesk.com**. Builds generate page-specific titles and descriptions, canonical URLs, Open Graph and Twitter card metadata, JSON-LD, a sitemap containing the six content pages, and robots.txt. The 404 page has no canonical and is marked noindex. Deployment and indexing still need to be configured as described below.

To update branding, replace `public/images/icon.png`. Replace `workspace.jpg` with a reviewed screenshot of sample data, maintaining its 1440 x 960 aspect ratio. Do not copy screenshots from a real user's workspace onto the website.

## Search and AI discoverability

The default build uses `https://capturadesk.com/`. SEO is generated by `scripts/seo.mjs` and `scripts/prerender.mjs` from the same page metadata used by the site. Crawlable, pre-rendered content supports conventional search and AI search discovery; no ranking or citation is guaranteed. There is no separate AI-only content or crawler-specific rendering.

Build settings are process environment variables (the standalone prerender script does not load .env files):

| Variable         | Default                   | Purpose                                                                                                  |
| ---------------- | ------------------------- | -------------------------------------------------------------------------------------------------------- |
| `SITE_URL`       | `https://capturadesk.com` | HTTPS origin, without a path, credentials, query, or fragment.                                           |
| `SITE_BASE_PATH` | `/`                       | Hosting directory; must start and end with a slash.                                                      |
| `SITE_INDEXABLE` | `true`                    | Set to `false` for publicly accessible staging builds. Adds noindex to every page and omits the sitemap. |

Example staging build in PowerShell:

```powershell
$env:SITE_INDEXABLE = 'false'
npm run build
Remove-Item Env:SITE_INDEXABLE
```

Rebuild with the default settings before publishing production. Staging robots.txt permits crawling so crawlers can read noindex; noindex is not access control. Use host authentication for private previews. Do not reuse the indexable production artifact on a public preview domain without a host-level noindex header.

The homepage describes the site and Windows app using WebSite and SoftwareApplication JSON-LD. Every content page has WebPage metadata. Offers, reviews, ratings, and installer download URLs are omitted because the site has no commercial offering, published reviews, or installer. This markup describes the product; it does not currently meet Google's software-app rich-result requirements for an offer and a rating/review. Do not invent these fields to pass a rich-results check.

The 1200 x 630 social preview is `public/images/social-card.png`. Its editable layout lives in `scripts/social-card.html`. After changing the branding, regenerate and inspect it, then rebuild:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run social-image
npm run build
```

## Publishing and search verification

1. Connect the static host to capturadesk.com and enable HTTPS. Redirect HTTP and www to `https://capturadesk.com`, retaining paths. Redirect `/index.html` to `/` and nested `/page/index.html` to `/page/`. Use trailing slashes consistently.
2. Serve existing pages with status 200 and missing pages with status 404 using the generated error page. Do not use an SPA fallback that returns 200 for missing URLs. Vite preview is for local review, not proof of production status or redirect behavior.
3. Enable Brotli or gzip compression. Cache hashed assets for a long time; revalidate HTML, sitemap, robots.txt, and unversioned images on new deployments.
4. Confirm the production pages have no noindex meta tag or X-Robots-Tag header, and that the host/CDN allows search crawlers to access content and images. Check `/robots.txt`, `/sitemap.xml`, and `/images/social-card.png` publicly.
5. Verify domain ownership in Google Search Console and Bing Webmaster Tools using the tokens those services provide. Submit `https://capturadesk.com/sitemap.xml` and inspect the homepage and getting-started page. These account and DNS steps are not performed by the build.
6. Validate JSON-LD with the Schema.org validator; use Google's Rich Results Test with the limitations above in mind. Test a shared link's image preview.
7. Run a mobile Lighthouse audit against the live HTTPS site and review performance, accessibility, and SEO. Local results do not measure the production host or real-user Core Web Vitals. Monitor indexing and search queries after launch.

Keep setup instructions, screenshots, availability, and privacy details accurate as the desktop app changes. Add useful examples based on real sample workflows, with the exported result and clear explanations. Avoid generating near-duplicate keyword pages.

References: [Google AI search guidance](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), [sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [site names](https://developers.google.com/search/docs/appearance/site-names), and [software app structured data](https://developers.google.com/search/docs/appearance/structured-data/software-app).
